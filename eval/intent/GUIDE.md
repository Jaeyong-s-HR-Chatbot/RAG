# 의도 분류 평가 기준

평가는 질문의 의미를 기준으로 정답을 붙인다. `guard`가 먼저 개인정보를 마스킹하고,
`classify`는 규칙으로 의도를 고른다. 이후 `build.py`는 `sensitive`와 `refuse`를 우선
처리하고, 질문 내용이 없으면 안내 후 종료한다. 나머지는 조회 도구, 규정 검색·계산,
답변 생성·검증 순으로 처리한다. 이 평가에서는 모델을 부르지 않는다.

## 정답 라벨

| 라벨 | 기준 |
| --- | --- |
| `rule` | 규정·절차·조건만으로 답할 수 있고 본인 자료 조회는 필요하지 않음 |
| `lookup` | 로그인한 본인의 저장 데이터만 확인하면 됨 |
| `both` | 본인 데이터와 규정 근거가 모두 필요함 |
| `sensitive` | 직장 내 괴롭힘·성희롱·폭언 등 고충이나 민감 주제 상담임 |
| `refuse` | 다른 직원의 개인정보·급여·인사정보 등 권한 밖 자료를 요구함 |
| `no_question` | 개인정보를 소개할 뿐 물어보는 내용이 없음. `build.py`의 내용 없음 판정 결과로 평가함 |
| `out_of_scope` | 인사 규정·본인 인사 데이터와 관계없는 질문 (날씨, 잡담, 재테크, 사내 IT·총무, 다른 조직의 제도 등). 안내 후 종료 |

`sensitive`와 `refuse`는 단순히 단어가 있는지가 아니라 문장의 목적을 본다. 다만 `징계`
처럼 민감 단어를 포함해도 일반 규정 자체를 묻는 문장은 `rule`로 채점한다. `no_question`은
민감·타인 조회가 아니면서 질문 내용이 없는 경우에만 적용한다.

## 헷갈리는 경계

| 경계 | 기준과 예문 |
| --- | --- |
| `rule` / `both` | 본인 조건·잔여 자료를 규정과 함께 대조해야 하면 `both`. 일반 제도 설명이면 `rule`. `병가 규정상 진단서 기준이 뭐야?` → `rule`; `내 병가 사용일과 진단서 기준을 같이 확인해 줘` → `both` |
| `lookup` / `both` | 이미 저장된 본인 잔액·급여·신청 상태만 묻는 것은 `lookup`. 규정 판단도 함께 요구하면 `both`. `내 연차 몇 개 남았어?` → `lookup`; `내 연차 잔여와 사용 기준을 같이 알려 줘` → `both` |
| 생애 이벤트 (결혼·출산·사망·이사·육아휴직·퇴직) | `event` 라벨은 쓰지 않는다 (2026-11-18 폐지). 주제가 아니라 필요한 것으로 나눈다: 규정만 있으면 되면 `rule`, 본인 데이터도 필요하면 `both`. `출산하면 어떤 휴가를 신청할 수 있어?` → `rule`; `퇴직할 때 남은 휴가와 정산 절차가 궁금해` → `both` (연차 잔여 조회) |
| `out_of_scope` / `rule` | 우리 회사 인사 규정으로 답하는 질문이면 `rule`, 회사 일이어도 인사 규정이 아니거나 다른 조직의 제도면 `out_of_scope`. `광역시 출장 여비는?` → `rule`; `KTX 승차권 환불 수수료는?`, `공무원은 연차 며칠이야?` → `out_of_scope`; `병가 쓰려면 진단서 필요해?` → `rule`; `감기약 뭐 먹어?` → `out_of_scope` |
| 결혼 혜택 | 결혼축하금은 생애 1회 한정으로 본다 (팀 결정 2026-11-18. 근거인 사내근로복지기금 운영규정은 자료에 아직 없음). 본인 결혼으로 받을 혜택을 물으면 `both`이고 도구는 `profile`·`family`(배우자 여부)·`requests`(과거 경조금 신청). 결혼 휴가 일수·신청 절차만 물으면 `rule`. `제가 결혼하는데 뭐 받을 수 있어요?` → `both`; `결혼 휴가 신청 절차가 어떻게 돼?` → `rule` |
| 신청 방법 / 신청 현황 | 앞으로 신청할 방법·서류·절차는 `rule`; 이미 낸 신청의 승인·결재 상태는 본인 건일 때 `lookup`. `경조금 신청 서류가 뭐야?` → `rule`; `내 경조금 신청 결재됐어?` → `lookup` |
| `sensitive` / `rule` | 본인의 피해·고충을 알리거나 도움을 구하면 `sensitive`. 중립적으로 규정 조항만 묻는 경우는 `rule`. `팀장에게 폭언을 들었는데 어떻게 해야 해?` → `sensitive`; `징계 규정의 소명 절차와 기한은?` → `rule` |

## 조회 도구와 계산 슬롯

`app/tools.py`의 이름: `profile`, `leave_balance`, `welfare_points`, `payroll`,
`family`, `requests`, `training`. `profile`은 본인 조회에 기본으로 포함된다.

- `annual_leave(hire_date, as_of)`: 입사일과 기준일. 날짜 대신 근속 표현만 있으면 `service_years`로 기록하고 `hire_date`를 만들어 내지 않는다 (예: `3` 또는 `{"years":2,"months":6}`)
- `overtime(ordinary_wage, overtime_hours, night_hours, holiday_hours)`: 통상임금과 연장·야간·휴일 시간
- `family_allowance(grade, family)`: 직급과 관계·나이·성별·부양 여부가 있는 가족 목록
- `business_trip(nights, days, region)`: 숙박 박수, 출장 일수, 지역

계산 `slots`에는 질문에 명시됐거나 기준일을 근거로 정규화한 값만 넣는다. 언급되지 않은 가족 나이·성별,
야간·휴일 시간은 추정해 채우지 않는다. 상대 날짜는 평가 기준일을 `note`에 쓰고 계산된 날짜를 기록한다.
현재 `calc` 연결은 연차·시간외와 기존 출장비만 지원하며, 가족수당은 함수만 있고 calc 단계에 연결되지 않았다.

## 미정

- 사내 IT·총무 문의(회의실 예약, 메신저 비밀번호)를 `out_of_scope`로 둘지, 담당 부서 안내로 따로 처리할지 정해지지 않아 `needs_review`로 표시했다.
- 간접적인 피해 암시처럼 명시적 민감 표현이 없는 문장은 문맥에 따라 `sensitive` 판단이 달라질 수 있다.
- 규정 단어가 없는 짧은 표현(예: “내 연차랑 기준 같이”)은 `lookup`과 `both`의 경계가 불명확하므로 `needs_review`로 표시한다.
